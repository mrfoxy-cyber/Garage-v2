How to read UML — symbols and arrows

Read each example from left to right. A hollow triangle points toward the parent class or interface; a diamond sits at the owning or grouping end.

SymbolMeaningExample
Inheritance
A child class inherits from its parent.		Car : Vehicle
The triangle points to Vehicle.
Interface implementation
A class fulfills an interface's contract.		Garage : IGarage
The triangle points to IGarage (illustrative).
Association
Objects have a structural relationship.		A driver is associated with a car.
Dependency / uses
The source uses the target.		A service uses a loader.
In the package view: a project reference.
Directed connection
Read the diagram's context and arrow label.		Component view: a project reference.
Sequence view: a message or call.
Composition / owns
A part belongs to at most one whole at a time; its lifetime is tied to the whole.		Garage ◆— ParkingSpot
The diamond is beside Garage.
Aggregation / groups
A whole groups parts that can exist independently.		Fleet ◇— Vehicle (illustrative)

Boxes, members and visibility

C classA abstract classI interfaceE enumS struct

In class views, a box names a type and lists its fields, properties and methods. Folder-shaped boxes group namespaces. Park(...) is a method or constructor; Vehicle Vehicle is a field or property.

+ public- private# protected~ UML package visibility

The C# diagrams spell out visibility: internal means the same assembly; protected includes derived classes. A package in UML and a C# assembly have different visibility rules.

Other common symbols

1 exactly one · 0..1 optional · * or 0..* zero or more · 1..* one or more. These labels describe how many objects participate at an association end.

Sequence diagrams: vertical dashed lines are lifelines; horizontal arrows are messages, and dashed arrows usually show replies. alt groups alternative paths, and [condition] is a guard. Activity diagrams: a filled circle starts the flow, a bullseye ends it, and a diamond is a decision or merge. State diagrams: arrows show transitions; their labels describe triggers, guards and actions.

These are reference examples. Current generated views show inheritance, interface implementation, namespace grouping and project references. The object template illustrates composition. Arrow labels and diagram type provide the context.
